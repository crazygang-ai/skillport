## 关键踩坑备忘（新 session 需要知道）

1. **`ProxySettingsActor` 用 `suiteName: String?`**（非 plan 原文的 `defaults: UserDefaults`）。Swift 6 strict concurrency 下 `UserDefaults` 传入 actor 会触发 "sending data races"，用 string 更干净

2. **测试无法使用 `Bundle.module`**。xcodegen 生成的 Xcode test target 不产出 SPM 的 `Bundle.module` 符号。用 `Tests/SkillportTests/TestSupport/TestBundleLocator.swift`（`Bundle(for: marker-class)` 模式）

3. **`SKILLMetadata` 是 `@unchecked Sendable`**。带 `extras: [String: Any]`，`Any` 非 Sendable；自定义 `==` 忽略 `extras`

4. **`uninstall` 删除 canonical**。删除所有 symlink + lockfile entry + `~/.agents/skills/<name>/` 整目录。若只想从单个 agent 撤，用 `toggleAgent(install: false)`

5. **Swift 6 微妙处**：
   - `MockURLProtocol` 用 `nonisolated(unsafe) static let _lock = NSLock()` 守静态 dict，`startLoading` 同步不用 Task（URLProtocol + Sendable 无法共存）
   - `FileWatcherActor` 用 `Unmanaged.passUnretained(self)` 把 actor 穿过 C callback，callback 里 `Task { await actor.emit }` 跳回隔离域
   - `SkillsModel` 的 `subscription` 属性是 `nonisolated(unsafe) private var`，`deinit` 读它调 `cancel()`（@MainActor class 的 deinit 默认就 nonisolated，**不要写 `nonisolated deinit` 关键字** —— 见踩坑 #9）
   - `SkillsModel.toggle` 主动调 `manager.rescan` 同步 `self.skills`（不靠 event stream 延迟传播），否则测试 flaky

6. **macOS 路径符号链接 gotcha**：`/var` 实为 `/private/var` 的 symlink，TempDir 测试里 `destinationOfSymbolicLink` vs `contentsOfDirectory` 返回不同表示，对比前两边都要 `URL.resolvingSymlinksInPath()` 归一化

7. **几个 commit 被 subagent 自作主张加了 `Co-Authored-By: Claude Sonnet 4.6` trailer**（0173c96 / ae65211 / cc66424），未来 dispatch subagent 时**显式禁止 trailer**

8. **plan 里 3 处小 bug 未修**（只影响 replay plan，不影响已提交代码）：
   - Task 4 的 `String(describing: Logger).contains("scanner")` 在 macOS runtime 下不成立
   - Task 12 写了空 `packages:` 块 + 漏了 SkillportTests 的 `GENERATE_INFOPLIST_FILE`
   - Task 45 的 `CodeEditor from: "1.5.0"` 不存在，实际最高 tag 1.2.6

9. **⚠️ 本机 Swift 6.3 vs CI Swift 6.0 语法差异**：
   - 本机 Xcode 26.4（Swift 6.3）能编通的部分语法在 CI `macos-15` + Xcode 16（Swift 6.0）上会编译失败
   - **已知不兼容**：`nonisolated deinit` 是 Swift 6.2+ 新语法 —— 现在代码库已都去掉，`deinit` 默认 nonisolated 即可
   - **规避方式**：push 前在本地 `sudo xcode-select -s /Applications/Xcode_16.app` 跑一遍（如装了），或把 CI 当 canary，发现失败直接 push fix
   - **决定要用 Swift 6.2+ 新特性时，同步升级 CI 的 `xcode-select` 到 `/Applications/Xcode_26.app`**
